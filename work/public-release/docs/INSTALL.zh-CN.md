# 安装、升级与双端接入

适用范围：Windows 和 macOS 桌面版，Obsidian 1.15.0 及以上。目前为手动安装试用版。

## 首次安装

1. 打开目标 Vault，备份已有内容。
2. 解压插件安装包，把 `plainob` 文件夹放到该 Vault 的 `.obsidian/plugins/` 下。自定义了 Obsidian 配置目录时，使用对应目录下的 `plugins/`。
3. 确认 `plainob` 下直接包含 `main.js`、`manifest.json`、`styles.css`，避免多嵌套一层文件夹。
4. 在 Obsidian“设置 → 第三方插件”中启用 PlainOB。首次启用会展示向导，也可通过命令面板运行“打开安装向导”。

Windows 可在资源管理器中打开 Vault 目录；macOS 可在 Finder 中按 `Command + Shift + .` 显示 `.obsidian` 等隐藏文件夹。安装路径始终相对于用户自己的 Vault。

## 四步向导

1. 选择新建系统、接入已有笔记库或接入已有工作台；选择界面语言，可选填写首页称呼，默认为空。
2. 新建模式选择英文编号目录、中文编号目录或自定义；已有库将 Inbox、Projects 等角色对应到现有文件夹。目录互不包含，不填盘符或完整系统路径。任务状态默认写入 `backlog / active / done`；已有库保留原规则。
3. 按需补齐三个模板、配置 Metadata Menu 下拉字段、提供 AI 整理规则。已有同名文档保留。Metadata Menu 需自行安装，目前只适配 0.8.12；需要写入其配置时，先暂时停用，完成后开启。AI 规则不会配置账号、模型或密钥。
4. 检查“创建 / 保留 / 追加 / 配置 / 阻止”明细，确认后执行。遇到阻止项先调整路径，再重新预览。

英文预设为 `00_Inbox`、`01_Projects`、`02_Areas`、`03_Resources`、`04_Archive`、`05_Templates`、`06_System`、`99_Attachments`。中文预设为 `00_收件箱`、`01_项目`、`02_领域`、`03_资源`、`04_归档`、`05_模板`、`06_系统`、`99_附件`。可选默认分类为通用领域和资料目录，不创建个人项目、示例任务或示例笔记。`Ideas`、`Configuration`、`Indexes` 等功能子目录使用固定名称。

界面语言和目录方案可分别选择；改界面语言不会改文件夹名称。安装后的文件夹整体改名和批量旧笔记迁移尚未提供，请不要直接改名后假设映射也会自动更新。

## 接入另一台 Windows 或 macOS 设备

1. 使用自己选择的同步或复制方式，让两端具备相同笔记、模板、清单、规则及附件。先等首次传输完成，再整理配置，避免两端分别生成不同版本的同名文件。
2. 在另一端单独安装相同版本的 PlainOB。第三方插件、模型登录等按需要另行设置。
3. 原设备运行“导出迁移配置”；在目标设备向导中导入，再按“接入已有工作台”检查预览。配置内只含 Vault 内相对路径，可跨 Windows 和 macOS 使用。
4. 如果目标端已生成过基础文件，向导仍保留它们；不会用原设备内容自动覆盖。需要采用同一版本时，请通过同步工具处理差异。
5. 两端打开同一篇测试任务，依次核对状态切换、完成/重新打开、同列排序和笔记属性。每次先等同步完成，再在另一端操作。同步冲突应在所用同步工具中解决。

无需使用特定同步服务。PlainOB 不连接服务器，不调整同步方向，也不决定冲突内容。

## 升级

保存编辑，关闭 PlainOB，然后只替换 `main.js`、`manifest.json`、`styles.css`，重新启用。保留自己的 `data.json` 和 `setup-backups`；不要用他人的配置覆盖。已有设置仍生效，无需重新走“新建系统”。降级前备份，较新格式的设置可能无法被旧版本读取。

插件文件夹的整份备份应存放在 `plugins` 目录之外，例如 Vault 外的备份目录。不要把 `plainob_backup` 等仍含 `manifest.json` 的副本放在 `plugins` 中，否则可能被识别为另一个插件。更新时确认三个运行文件直接位于正在使用的 `plainob` 文件夹内；Mac 上用 `Command + Q` 完全退出后重新打开，再核对版本。

目前使用上述手动方式。也可选用 [BRAT](https://tfthacker.com/BRAT) 添加 `GavinYanCQ/obsidian-plainob-dashboard` 并检查更新；BRAT 会下载更新并重新加载插件。社区上架后，可在 Obsidian“设置 → 第三方插件 → 检查更新”中更新 PlainOB。Obsidian 的社区插件默认不会自动更新，仍由使用者决定何时安装。

Windows、macOS 上的每个 Vault 分别维护插件版本；笔记同步完成不代表插件代码也已升级。更新后分别核对版本号。模板、分类清单和 AI 规则属于使用者的文件，升级代码默认保留，不会用新默认模板覆盖个人修改；涉及这些文件的新版变更，会单独说明。

参考：[Obsidian 更新说明](https://help.obsidian.md/community-plugins)。作者发布新版的步骤见[贡献说明](../CONTRIBUTING.md#publishing-an-update--发布更新)。

## 中断、备份与卸载

安装执行记录和被修改配置的原内容保存在配置目录下 `plugins/plainob/setup-backups/<执行编号>/`。向导中断后可以“检查并继续上次安装”；目标文件被编辑时停止，不覆盖。不会自动删除已创建的文件。

卸载插件不会删除笔记和已创建的目录；任务属性也留在 Markdown 中。若需恢复配置，先停用对应插件，再按执行记录恢复备份。

## 常见问题

- **Metadata Menu 提醒安装 Dataview**：属于其可选功能提示。PlainOB 和普通列表下拉不需要 Dataview；可在 Metadata Menu 的 Global settings 中打开 Disable dataview notice。
- **下拉菜单没出现**：确认安装并开启 Metadata Menu，适配版本为 0.8.12，且 FileClass 没有覆盖该字段。也可以直接在原生属性中编辑，工作台不依赖下拉工具运行。
- **另一台设备看不到变化**：先检查同一篇 Markdown 的属性是否已同步；迁移配置不传输笔记。再处理同步工具的冲突或重启后的索引问题。
- **目录被文件占用、大小写或 Unicode 名称冲突**：向导停止并提示。请自行确认正确位置后重新配置，不会自动删除或覆盖。
